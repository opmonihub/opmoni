# Implementation gap map and recommended priorities

Recorded 2026-10-24. Application baseline: `f8efb50ad69e23a872e5b65ab18fff48b86f3590` on `main`.

## Scope, evidence and assumptions

This is a source-based capability comparison and prioritization, not an implementation change or a live-production audit. The assumed next objective is safe operation of an accounting office plus a general-purpose commercial ERP. Retail, transport and services-specific priorities are conditional on the intended first customers.

References inspected:

- The full local `reference/sistema` repository, whose HEAD is `e7b77beccdad983ddd990c0a045be750fc3f7e25`, and the pinned `reference/sistema-e7b77be` snapshot. The snapshot contains extracted route text files, not an executable `routes/web.php`. Reference presence proves a source comparison opportunity, not current production reliability or approval to copy the feature.
- [The pinned source synchronization manifest](../../scripts/sync-sistema-full-core.sh), including its controller/domain inventory.
- [MarketUP operation-nature research](2026-10-23-marketup-operation-nature/report.md). Adopted CFOP/profile/provenance ideas have already been implemented; the research is not a universal fiscal rulebook.
- `.dashboard` is the visual/component reference; it is not the authority for additional business features.
- [Product decisions](../architecture/product-decisions.md), [current reconciliation](../architecture/system-spec-reconciliation.md), canonical specs, active routes, actual frontend consumers and native domain services.
- [Final local acceptance](2026-10-23-erp-template-product-setup/final-local-acceptance.md), which records complete local checks and explicitly excludes live-provider acceptance.

No application, provider, database, browser or test runtime was started. No credentials, environment values, production flags, reference files or application sources were changed. Searches for absent capabilities cover native routes, ERP services/models, frontend consumers and configuration; absence statements mean no complete native workflow was found in that inspected surface. The full local reference is untracked in the parent repository and must not be published automatically.

Priority meanings: **P0** before broad real-customer use; **P1** next delivery cycle for routine operation; **P2** after the base is operational or when its target segment requires it; **P3** expansion/deferred architecture. These are recommendations for a new backlog, not reopened failures of the completed 58-task change.

## Recommended delivery order

1. **Close access and release risks:** G01, CI gate G09 and operational restore evidence L03. Run live acceptance L01/L02 only through a separately approved provider/credential scope.
2. **Finish daily money workflows:** G02 first; then G03/G04 on top of the existing financial journal. Add G05 before onboarding businesses with existing balances. Validate installment returns and duplicate charge/reconciliation behavior explicitly.
3. **Remove fiscal data-entry blockers:** G06 and a bounded G07 selected from the first customers' real operations; complete L01 for those exact scenarios. Add G08 document/collection delivery once authoritative artifacts and charges exist.
4. **Choose the target segment:** G10 moves forward for retail; G13 moves forward for service companies; G11 moves forward for period closing. G12 and G14 should follow an explicit need. Keep G15 deferred unless the integrated architecture becomes a concrete constraint.
