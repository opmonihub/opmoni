# Nuxt Dashboard Template: UI/UX Pattern Map

Read-only source map for the actual repository template at `/home/obsidian/dev/opmoni/.dashboard`, prepared as a reusable reference for the ERP UI comparison. This is source evidence, not a visual audit: no template server, browser, build, tests, external services, or install were run. The root coordinator owns the browser comparison.

## Scope and version evidence

The inspected source is the checked-in `.dashboard` template, not the public live demo. Its README identifies the Nuxt Dashboard Template and advertises a collapsible sidebar, keyboard shortcuts, light/dark mode, command palette, and multiple pages ([README.md](/home/obsidian/dev/opmoni/.dashboard/README.md:1)). `package.json` declares Nuxt `^4.6.0`, Nuxt UI `^4.11.3`, Vue `^3.5.43`, Tailwind CSS `^4.3.3`, and pnpm `12.11.2` ([package.json](/home/obsidian/dev/opmoni/.dashboard/package.json:13)); the lockfile resolves Nuxt `4.6.0`, Nuxt UI `4.11.3`, Vue `3.5.43`, and Tailwind `4.3.3` ([pnpm-lock.yaml](/home/obsidian/dev/opmoni/.dashboard/pnpm-lock.yaml:171)). These are lockfile versions, not a runtime `nuxt info` check.

The actual ERP comparison worktree was observed at `810506f` on `codex/erp-finalization-recovery`. It had pre-existing untracked ERP outputs and a test file; all were left untouched. `.dashboard` is absent from that worktree, so inspection used the user-designated repository-root source.

## ERP-safe pattern extraction

The useful reference is the template's composition grammar: dashboard group/sidebar/panel; navbar leading/right slots; toolbar for scoped filters; standard Nuxt UI inputs/forms/cards/tables/menus/overlays; semantic token classes; and a deliberate small-screen inbox-to-slideover transition. The customers table is the clearest source for a rich table state model and per-slot `UTable` styling. Settings pages are useful for heading/action and field-card composition. These patterns can be adapted while keeping Opmoni's current route, tenant, authorization, account-context and copy conventions.

The template's `server/api/*` handlers return hard-coded in-memory fixtures: customer rows ([customers.ts](/home/obsidian/dev/opmoni/.dashboard/server/api/customers.ts:4)), long synthetic mail bodies ([mails.ts](/home/obsidian/dev/opmoni/.dashboard/server/api/mails.ts:1)), member fixtures ([members.ts](/home/obsidian/dev/opmoni/.dashboard/server/api/members.ts:3)), and notification fixtures ([notifications.ts](/home/obsidian/dev/opmoni/.dashboard/server/api/notifications.ts:4)). UI mutations are mostly toast, console output, or timeout. Do not copy the route/API/data assumptions, client-only pagination, fake authentication/team switching, or sample business terminology into ERP flows.

- Nuxt UI defaults are not redefined as facts here. Where a component omits `size`, `variant`, or other props, this report calls that an omitted-prop/library-default use; installed component internals were not opened. The report gives explicit local overrides where the template source supplies them.
- Lockfile pins are source evidence only; runtime dependency installation/routing telemetry was not queried. Luna/medium routing remains unconfirmed.
- The only write made for this task is this report. No template/app source or ERP implementation was edited.
