# Access, office operations, and platform UI/UX source review

Date: 2026-10-20. Application snapshot: worktree `erp-finalization`, frozen source HEAD `810506f`. Reference: the actual `/home/obsidian/dev/opmoni/.dashboard` files, not the upstream website. Paths below are relative to the worktree root unless prefixed `.dashboard/`, which refers to the repository-root reference directory.

## Scope and evidence limits

This review covers **all 50 Vue page files outside `app/pages/erp/`**, including the platform's `/admin/erp/*` pages, their parent shells, public access, office operations, context selection, and the office side of ERP approval. Page files and routable screens are different counts: parent files supply shells and dynamic files expand into multiple valid URLs. The appendices enumerate both.

Evidence is source inspection: pages, components, composables, middleware, transport, navigation registries, selected Laravel route/controller contracts, canonical specs, and product decisions. No server, browser, tests, builds, installs, provider calls, account changes, or credential reads were performed by this reviewer. Source-supported risk is identified explicitly; visual overflow, keyboard focus, final computed contrast, backend availability, mail delivery, fiscal/SERPRO production acceptance, WhatsApp delivery, and actual runtime model routing remain unverified. The coordinator owns runtime/browser/detector evidence. Requested worker model/effort are not execution telemetry.

Impeccable's Operate/audit framing informs the review: honest action outcomes, readable data density, clear authority, error recovery, keyboard names, mobile equivalence, and incumbent Nuxt UI conventions. Launcher/context and runtime passes belong to the coordinator; no duplicate detector was run here. No application source was edited.

## Executive assessment

The office product is substantially implemented beyond the reference dashboard. Clients, Fiscal, Monitoring, Work, Equipe, certificates, WhatsApp, and platform management call real versioned APIs. Shared table families, accessible row-action triggers, sticky error handling, context-reset behavior, legal-action consent, and platform/tenant separation are valuable adaptations to preserve.

The most serious gaps are **misleading successful actions in Inbox, inert account-security controls, and client detail requests that can misidentify outages or retain the wrong record after navigation**. Other systemic problems are inconsistent error semantics, mixed demo/live navigation, incomplete dependent pickers, weak feedback from member-management failures, and a less mature ERP subscription platform list. No P0 was established by this read-only source pass; that is not a security acceptance statement.

## Reusable state and interaction standards

1. **Identity first:** the current office and Company are visible in their own selectors; a detail ID or delegation change invalidates pending loads, stale editors and selection before actions can run. Request ownership should follow the guarded platform loaders and ERP approval component.
2. **Four distinct read states:** initial loading, successful empty, failed initial read with retry, and failed refresh retaining clearly marked stale data. A 404 or `catch(() => [])` is not automatically “nothing exists”. `useRetryableLoad.ts:50-84` and `ErrorRetryAlert.vue` already provide a starting contract.
3. **Honest writes:** success follows the actual API acknowledgement; queued capture/send is labelled queued; delivery is only claimed from delivery evidence. The certificate capture copy distinguishes queued/blocked/not queued (`CertificateModal.vue:41-65`), while Inbox violates this rule.
4. **Validation and blocked writes:** show fields for 422, business/plan/last-admin reasons near the control, session-loss separately, and retryable service failure without discarding ordinary inputs. Protect submit/action duplication and do not allow a stale dependent catalogue to overwrite stored configuration.
5. **List behavior:** maintain sort/filter/visible columns; reset server page when filters change; recover pages beyond new last page; preserve or invalidate selection according to snapshot semantics. Provide an explicit filtered-empty clear action. Differentiate loaded-page selection from all-filtered selection; Clients implements server snapshots and exclusions.
6. **Mobile equivalence:** the Client, Fiscal, Monitoring and Work sheet families contain card/list alternatives; office Admin remains a horizontal table family. Every supported action must remain reachable in the small-screen alternative. Source presence does not prove usable hit targets, focus, tabs, scroll, or no clipping.
7. **Theme and copy:** retain Portuguese locale and reference tokens, translate template residue, test supported light/dark/neutral/primary combinations, and document scope/persistence of theme controls. Do not infer WCAG contrast from a token's name.
8. **Modal/slideover lifecycle:** keep the originating record and focus, block close during an irreversible in-flight operation when needed, clear sensitive material at close/completion, and retain safe data/errors for correction. Client list already restores originating focus (`[documento]/[[situacao]].vue:238-252`).
