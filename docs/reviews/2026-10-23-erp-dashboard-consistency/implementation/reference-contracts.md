## Native selector compatibility boundary

`frontend/app/components/erp/catalogs/ErpCatalogReferenceSelect.vue` is reusable only for verified native contracts:

- Requires `number | null` model (`:7,19-21`); updates accept only positive safe integer IDs and otherwise set null (`:74-80`). That is incompatible with arbitrary existing text IDs, leading-zero strings or beyond-safe-integer identifiers without a separate verified contract.
- Reads active rows, uses supplied `labelKey`, preserves current detail record as a disabled option if absent from active page, shows archived/inactive labels (`:35-71`). It loads `${path}/${id}` when current ID is not in the page (`:97-117`). This request itself assumes the model belongs to that exact path namespace; it must not be attempted for an unverified legacy value.
- A selection is valid only when record ID matches, status is active, read authority holds, and no list/detail pending/error exists (`:48-55`). It can display an archived current label while emitting invalid; consumers must not use that validity as authority to clear a historically supported settings value or block an unrelated settings save.
- On context changes it aborts/clears cached private labels and blocks resolution of the previous selected ID (`:83-107`), without rewriting the model. It retains model on detail errors (`:118-125,237-238`) and reports preserved selection on list errors (`:217-224`). Manual clear or invalid selection event can still set null, so this is not a raw-value-preserving legacy adapter.
- `frontend/app/composables/useErpCatalogList.ts:8-22,38-57` ties paths to separate native catalog read permissions; unknown paths are unreadable. Catalog grants cannot be inferred from settings permissions. `frontend/shared/utils/erpCatalogs.ts:28-32` supplies search/page query; `backend/app/Erp/ErpCatalogScope.php:106-115` defaults lists to active, supports search/page/per_page and status all/archived. `backend/app/Http/Controllers/Api/V1/Erp/Catalogs/ErpCatalogController.php:33-78,98-110` returns paginated data/meta, scoped by Company and establishment where relevant, and a detail endpoint that does not filter archived status. A detail 404 may mean unavailable/not visible; it does not prove a settings value is invalid.
- Native catalog mutation helper allows unchanged historical IDs only where consumers explicitly pass them (`backend/app/Erp/ErpCatalogScope.php:33-55`). Settings update never invokes it. Its policy must not be silently imported into legacy settings.
